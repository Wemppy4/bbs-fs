# Редактор анимаций текстур (`.mcmeta`) внутри редактора текстур — план

Статус (2026-08-27): план подтверждён Вемпи; Э0 `a22f7d9c2`, Э1 `23a8317ec`, Э2 — сделаны, ЖДУТ ПРОГОНА; Э3 не начат.

Что уже есть в коде (для прогона):
- `TextureAnimation` (`ui/dashboard/textures/data`) — чтение/запись `.mcmeta` с круговой сохранностью; `Document.animation` только в памяти, `snapshot/restore` для undo, операции с картинками (`bakeOffsets/appendImage/duplicateImage/removeImage`).
- Холст показывает окно кадра (`UIPixelsEditor.frameX/frameY`, `renderLayers`, `getHoverPixel`), `,`/`.` листают, `Alt+N` — новый кадр.
- Полоса `ui/dashboard/textures/frames/UIFramesPanel` (транспорт: ▶ ◀ ▶| счётчик, длительность, +) + `UIFrameStrip` (`UIItemGrid.horizontal()` — новый режим общего грида, `GridLayout.strip()`); ПКМ по ячейке; вертикальный сплиттер `texture_painter.frames`; иконка FILM в полосе действий, выключение с подтверждением.
- Отличие от эскиза: транспорт — отдельной строкой 20px НАД ячейками (а не слева от них), чтобы ряд ячеек был во всю ширину.

Решения Вемпи (2026-08-27):
- `.mcmeta` — единственное хранилище настроек анимации. `.dat` — только проект (слои), как сейчас.
- Таймлайн = **порядок показа** (список `frames` из `.mcmeta`), а не физический порядок картинок в PNG.
- Это **редактор существующего формата**, не новая технология: всё, что умеет редактор, выражается в `.mcmeta`; всё, что уже лежит в `.mcmeta`, редактор сохраняет как было.

## 0. Словарь (чтобы дальше говорить одними словами)

- **Полоса** — сама PNG-картинка на диске: кадры-картинки лежат друг под другом (так читает и BBS, и ваниль).
- **Картинка** — один кусок полосы размером «кадр» (`width` × `height` из `.mcmeta`). Картинки нумеруются сверху вниз: 0, 1, 2…
- **Кадр** — запись в порядке показа: «показать картинку №N столько-то тиков». Это квадратик в таймлайне. Один и тот же номер картинки может встречаться в нескольких кадрах.
- **Окно кадра** — кусок полосы, который холст показывает и даёт рисовать: картинка текущего кадра.
- **Тик** — 1/20 секунды, единица времени `.mcmeta`.

Формат `.mcmeta`, который редактируем (раздел `animation`):

```json
{
  "animation": {
    "frametime": 2,            // длительность кадра по умолчанию, тики (по умолчанию формата — 1)
    "width": 16, "height": 16, // размер картинки; по умолчанию квадрат min(ширина, высота) полосы
    "interpolate": false,      // ваниль смешивает кадры; BBS игнорирует — только сохраняем как было
    "frames": [0, 1, {"index": 2, "time": 5}, 1]   // порядок показа; нет списка = все картинки по порядку
  }
}
```

## 2. Главные решения

### 2.1 Кадр — окно в полосу, не отдельный документ
Документ остаётся одним холстом-полосой, слои тянутся на всю полосу. Холст показывает только окно кадра. Следствия:
- `.dat` не меняется; старые `.dat` открываются как есть.
- Undo не переписывается: `PixelsUndo` уже хранит пиксели слоя; структурные операции идут через снимок документа.
- Сохранение = как сейчас + запись `.mcmeta`. Загрузчик игры не меняется.
- Слои общие для всех кадров (как в Aseprite): слой «контур» есть в каждом кадре.
- Инструмент «переместить» двигает слой целиком, во всех кадрах. Это принято; отдельно не чиним.

### 2.2 `.mcmeta` — единственная правда
- В `Document` анимация живёт **только в памяти** (`document.animation`, `null` = не анимирована) и **не пишется в `.dat`**.
- При открытии: есть `.mcmeta` → анимация из него (даже без `.dat`). Нет — не анимирована.
- При сохранении: анимация есть → пишем `.mcmeta`; анимации нет, а файл на диске был → **удаляем** `.mcmeta` (выключение анимации — явное действие, см. 4.6).
- **Круговая сохранность**: при чтении держим весь разобранный `MapType` файла; при записи переписываем только `frametime`, `width`, `height`, `frames`. Остальные ключи (`interpolate`, чужие разделы вроде `texture`) уезжают обратно нетронутыми.

### 2.3 Таймлайн = порядок показа
- Ячейка = кадр = `{index, time}`. Перестановка кадров **не двигает пиксели** — меняется только список.
- Дублирование кадра = новая картинка в конце полосы (копия) + новый кадр после текущего.
- Удаление кадра = убрать запись; если на картинку больше никто не ссылается — вырезать её из полосы (все слои становятся ниже, номера картинок выше неё сдвигаются на −1 во всех кадрах).
- В `.mcmeta` список `frames` пишется **только** если он не «по умолчанию» (порядок `0..N-1` и все длительности = `frametime`). Простая анимация даёт такой же чистый файл, как сейчас.
- Кадр с номером картинки за пределами полосы (битый файл) показывается ячейкой-заглушкой и при сохранении уезжает как был — редактор не чинит чужие файлы молча.

## 3. Модель данных

### 3.1 Новый класс `ui/dashboard/textures/data/TextureAnimation`
```
public class TextureAnimation
{
    public int frametime = 2;          // при создании новой анимации; при чтении дефолт формата = 1
    public int width;                  // 0 = «по умолчанию» (квадрат)
    public int height;                 // 0 = «по умолчанию»
    public final List<Frame> frames;   // порядок показа, всегда материализован (даже если в файле списка нет)
    private MapType source;            // весь разобранный .mcmeta для круговой сохранности (может быть null)

    public static class Frame { public int index; public int time; /* 0 = frametime */ }

    static TextureAnimation read(File mcmeta, int stripW, int stripH);   // null, если файла нет/не читается
    static TextureAnimation create(int stripW, int stripH);              // новая: одна картинка = вся текстура, один кадр
    MapType toMcmeta();                 // source (или пустой) с переписанным разделом animation
    int frameWidth(int stripW);  int frameHeight(int stripH);  int imageCount(int stripH);
    int length();                       // сумма длительностей, тики
    int frameAt(int tick);              // номер кадра на тике (для проигрывания) — та же логика, что в AnimatedTexture
    boolean isDefaultSequence();        // 0..N-1 и все time == 0
}
```
Правила записи: `width`/`height` пишутся, только если не равны тому, что загрузчик посчитал бы сам; `frames` — только если `!isDefaultSequence()`; в записи кадра `time` опускается, если равен `frametime` (тогда кадр пишется числом).

Чтение/запись через `DataToString.read(File)` / `DataToString.writeSilently(file, map, true)` — как уже делает браузер.

### 3.2 `Document` — что добавляется
- `public TextureAnimation animation;` (runtime, не сериализуется в `.dat`).
- `snapshot()` / `restore(MapType)` — снимок для undo = `toData()` + анимация. `toData()/fromData()` остаются форматом `.dat` (без анимации). `LayerStateUndo`, `recordLayerChange`, снимок инструмента «переместить» переводятся на `snapshot/restore`.
- Операции с картинками (все — через `recordLayerChange`, один шаг undo):
  - `bakeOffsets()` — впечь смещения слоёв в пиксели (смещение = временная штука инструмента «переместить»; операции с рядами делаются в чистых буферах). Вызывается первым внутри каждой операции ниже.
  - `appendImage()` → `resize(width, height + frameH)`; возвращает номер новой картинки.
  - `duplicateImage(i)` → `appendImage()` + копия рядов `i*h..(i+1)*h` в каждом слое (`Pixels.drawPixels`).
  - `removeImage(i)` → вырезать ряды в каждом слое, `height -= frameH`, сдвинуть `index > i` во всех кадрах.
  - `frameWidth()/frameHeight()/imageCount()` — обёртки над `animation` с размерами документа.
- Ревизия: `int revision`, растёт в `UIPixelsEditor.wasChanged()` — превью модели пересобирает кадры только когда она изменилась.

### 3.3 Открытие и сохранение
`UITexturePainter.loadDocument(link)`:
1. `.dat` есть → слои из него, иначе из пикселей текстуры (как сейчас).
2. `.mcmeta` есть → `document.animation = TextureAnimation.read(...)`.

`UITextureEditor.writeTexture(link)` (порядок важен для вотчдога — он перечитывает по каждому файлу, к моменту чтения PNG `.mcmeta` уже должен лежать рядом):
1. `.mcmeta`: `animation != null` → записать; иначе удалить, если есть.
2. PNG (сплющить), 3. `.dat`, 4. колбэки — как сейчас.

«Сохранить как» — то же с новым путём (`.mcmeta` пишется рядом с новым PNG).

│    │  скорость  ║                              │  руется)│
│    │  размер    ╟──────────────────────────────┤         │
│    │ слои       ║ ▶ ◀ ▶| 3/8 [дл. ▭] 🧅 + │▢▢▣▢▢▢▢▢│         │
└────┴────────────╨──────────────────────────────┴─────────┘

### 4.1 Окно кадра на холсте (`UIPixelsEditor`)
- Новое состояние: `frameX, frameY, frameW, frameH` в координатах документа. Не анимирована → окно = весь документ (ничего не меняется в поведении).
- `w/h` холста (`UICanvasEditor`) = размер **окна**; центрирование/зум — как были.
- `getHoverPixel` → прибавляет `frameX/frameY`: всё, что дальше (кисть, заливка, пипетка, выделение, перемещение), уже работает в координатах документа и не меняется.
- Отрисовка слоя: рисуем **пересечение** прямоугольника окна с прямоугольником слоя (слой со смещением), куском текстуры через `Batcher2D.texturedBox(..., u1, v1, u2, v2, tw, th)`. Пересечение — потому что за краем текстуры слоя при обёртке `REPEAT` вылезет соседний кадр.
- Клип холста — по прямоугольнику окна, а не по всему элементу (иначе слой со смещением «протечёт» пикселями соседнего кадра).
- Маска выделения остаётся размером с документ (`selectionMaskPixels` w×h документа), рисуется куском окна; `Scale` шейдера = `ширина окна на экране / frameW`.
- Затрагиваемые места (по текущим строкам): `renderCanvasFrame` 1714–1733, `renderSelection` 1029–1031, `copyPixel` 1396–1397, `createSelectionMask`/`fillSelectionMask`/`buildSelectionsFromMask`/`updateSelectionMaskTexture` 821–985, `selectLayerBounds` 290 — везде, где `this.w/this.h` означает «документ», перейти на `document.width/height`; где «окно» — оставить.
- Подпись под курсором (`UITexturePainter.renderHoverInfo`): координаты внутри кадра + «кадр 3/8».
- `UITextureEditor.setFrame(int position)` — ставит окно по кадру `animation.frames.get(position)`; `getFrame()`.

### 4.2 Луковая кожа
- Тумблер в транспорте (иконка `ONION_SKIN`), состояние в painter'е (на сессию).
- Перед слоями текущего кадра рисуем предыдущий кадр (по порядку показа) тем же кодом «кусок окна», с альфой 0.35. Только предыдущий; следующий — потом, если попросит.

### 4.3 Полоса кадров — `ui/dashboard/textures/frames/UIFrameStrip extends UIItemGrid<TextureAnimation.Frame>`
- Элемент = объект `Frame` (сравнение по ссылке — переживает перестановки). `multi()`, `sorting()`.
- Хуки: `reorder` → переставить в `animation.frames`; `onDelete` → удалить кадры (см. 2.3); `callback` → `editor.setFrame(первый выбранный)`.
- Ячейка (`renderCell`): чекерборд + живая миниатюра картинки (кусок сплющенной/послойной текстуры — тот же приём, что на холсте, без луковой кожи), номер кадра слева сверху, `×3` справа снизу если длительность своя; **ховер и активный = только обводка** (`CellPainter.frames`), без заливки; полоса действий при наведении: DUPE, REMOVE (`CellActionBar`, как у текстур). Битый номер картинки → заглушка (чекерборд + `?`).
- ПКМ по ячейке (один порядок, как в браузере): вставить пустой до / после → дублировать → длительность… (для всех выбранных) → удалить (красное, последним).
- **Горизонтальный режим** — доработка общего кода, не новый виджет:
  - `GridLayout.strip()` — все ячейки в один ряд (`perRow = count`), `getContentWidth()`.
  - `UIItemGrid.horizontal()`: `scroll.direction = HORIZONTAL`; `originX()` вычитает скролл, `originY()` — нет; `relayout` пишет `scroll.scrollSize` шириной; отсечение невидимых ячеек в `renderCells` по X; `scrollIntoView` по X. Вертикальные гриды не должны измениться ни на пиксель — проверить браузер текстур и морфинг.
- Транспорт слева от ячеек (одна строка 20px): `PLAY/PAUSE`, `FRAME_PREV`, `FRAME_NEXT`, текст «3/8», трекпад длительности (пишет `time` во все выбранные кадры; пусто/0 = по умолчанию), `ONION_SKIN`, `ADD` (новый пустой кадр после текущего).
- Проигрывание: по `context.getTick()` (тики клиента, 20/с — та же скорость, что в игре); во время проигрывания холст показывает текущий кадр проигрывания, рисовать можно (никаких особых веток). Переключение вкладки/редактора останавливает.
- Размещение: `editorHost` делится по вертикали — холст сверху, полоса снизу; высота полосы — `UISplitter.pixels("texture_painter.frames", …).vertical()` (как два существующих сплиттера painter'а). Полоса скрыта, когда текстура не анимирована.
- Одна полоса на painter, привязка через `setEditor` — ровно как `UILayersPanel`.

### 4.4 Клавиши (категория `pixels`, `.inside()` на painter'е)
- `,` — предыдущий кадр, `.` — следующий (`repeatable()`), `Alt+N` — новый кадр. Ключи: `Keys.PIXEL_FRAME_PREV/NEXT/ADD`.

### 4.5 Секция «Анимация» в колонке настроек
- `UISection(...).remember(folds, "animation", true)` в `options` (после кисти). Видна только у анимированной текстуры.
- Поля: «Скорость (тики)» = `frametime` (трекпад, ≥1); «Ширина кадра», «Высота кадра» (трекпады, 1..размер документа; пусто = по умолчанию). Смена размера кадра пересчитывает число картинок = `высота полосы / высота кадра` (остаток не показывается — как в загрузчике).
- `interpolate` не показываем: BBS его не использует, а тумблер «который ничего не делает» только путает. Сохраняется как был.

### 4.6 Включение/выключение анимации
- Иконка `FILM` в верхней полосе действий (рядом с «размер» / «извлечь»), подсветка = анимирована.
- Включить: `animation = TextureAnimation.create(...)` — одна картинка = вся текущая текстура, один кадр. Появляется полоса и секция.
- Выключить: если на диске есть `.mcmeta` — подтверждение «Убрать анимацию? При сохранении `.mcmeta` будет удалён». Порядок показа теряется, пиксели остаются (полоса как была).

### 4.7 Модель-превью
- `UIModelPreviewPanel`: если `animation != null` — под фейковый линк кладём `AnimatedTexture` в `TextureManager.animatedTextures` (а не в `textures`). Собираем её **тем же** `AnimatedTexture.load(поток из toMcmeta(), сплющенные пиксели)` — ноль своего разбора, поведение 1:1 с игрой. Пересобираем только при смене `document.revision`. Закрытие превью — убрать и удалить.

### 4.8 Мелочи в браузере
- Панель свойств: вместо «анимировано» — «Анимация: 8 кадров, 2 тика» (через `TextureAnimation.read`).
- ПКМ «Создать .mcmeta» → «Сделать анимированной»: открывает редактор с включённой анимацией (голый файл больше не пишем).

## 5. Этапы (каждый — отдельный коммит, компилируется, прогоняется)

### Э0 — `.dat` ездит с файлом (баг, не зависит от остального)
- `TextureFiles`: `sidecars(file)` = [`.mcmeta`, `.dat`]; `rename`, `move`, `duplicate`, `copyInto` (через `copyAsset`, отсутствующий молча пропускается), `delete` — по всем.
- Проверить руками: переименовать/переместить/дублировать/удалить текстуру со слоями — слои на месте; Ctrl+Z перемещения тоже тянет `.dat`.

### Э1 — модель + окно кадра (без полосы)
- `TextureAnimation` (чтение/запись, круговая сохранность, дефолты).

## 6. Не делаем сейчас (отложено, не отклонено)
- `interpolate` в загрузчике `AnimatedTexture` (ваниль смешивает соседние кадры; у нас нужна отдельная работа с шейдером/смешиванием на CPU).
- Показ одной картинки в нескольких кадрах через интерфейс (формат и модель это уже умеют; нужна только команда «вставить ссылку на картинку»).
- Импорт кадров из отдельных файлов (зеркало «Извлечь кадры»).
- Луковая кожа для следующего кадра, настройка её прозрачности.
- Метки/циклы/теги кадров — формат этого не знает, значит и мы нет.

## 7. Ловушки и риски
- Обёртка текстуры слоя по умолчанию не `CLAMP` → кусок за краем тянет соседний кадр. Рисовать только пересечение окна и слоя (4.1).
- `calculate()` в `UICanvasEditor` возвращает **общий** `Area` — копировать значения в локальные переменные до следующего вызова (уже прокомментировано в `renderSelection`).
- Вотчдог перечитывает текстуру по каждому файлу отдельно — писать `.mcmeta` **до** PNG (3.3).
- `LayerStateUndo` хранит полный снимок с пикселями — для операций с картинками это нормально (редкие), но не вешать на него трекпад длительности без `mergeTag`.
- `Selection<T>` по ссылке: после `removeImage` объекты `Frame` живы, но их `index` сдвинут — обновлять выбор явно, не полагаться на позиции.
- Горизонтальный режим грида трогает общий код браузера текстур и морфинга — прогон обоих обязателен.
- Не править `.json` локализации через PowerShell (BOM) — только Edit.
