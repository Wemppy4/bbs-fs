# BBS FS для Forge 1.12.2: первая рабочая база

Версия: `2.8-1.12.2-alpha.1`, ветка `1.12.2`, 2026-10-04.
Это поэтапный порт текущего BBS FS. Полного набора функций современной версии
здесь пока нет. Ядро данных, cubic-модели, позы, Molang и анимации взяты из BBS FS;
Blockbuster и McLib использованы как технический референс платформы 1.12.2.

## Текущий этап переноса исходного UI — 2026-10-04

В рабочем дереве перенесены исходные OrbitCamera/UIOrbitCamera/CameraController
и UIModelRenderer с нативным Forge рендером. Игровые прогоны подтверждают полёт,
orbit/pan/zoom, roll/FOV/free-look, ортографику мира и восстановление игрового вида.
Исходный viewport рендерит ModelForm/MobForm/BillboardForm/ExtrudedForm; настоящий
RGBA framebuffer выбирает форму по пикселю и рисует подсветку. Проверены матрицы,
viewport/FBO/shader state, GL0 и отсутствие новых ошибок рендера.

Отчёты: `build/reports/forge1122-original-camera-smoke.json` и
`build/reports/forge1122-original-viewport-smoke.json`. Это проверки компонентов
на отдельных стендах AI Helper, а не подтверждение готового Dashboard/редакторов.
Модель пока выбирается целиком; bone picking, полный Gizmo и связанные редакторы
ещё переносятся. Инструкции alpha ниже описывают ранее выданный артефакт, а не
полноту текущей незавершённой рабочей сборки.
## Установка и работа

Нужны Minecraft **1.12.2**, Java **8** и Forge. Проверенная версия Forge —
**14.23.5.2847**. Другие сборки Forge и сторонние модпаки отдельно не проверялись.
Поместить `bbs-fs-2.8-1.12.2-alpha.1.jar` в `mods`. Файлы с суффиксами
`-dev` и `-sources` для установки не предназначены. JOML включён в JAR;
Fabric, Blockbuster, McLib, Metamorph и AI Helper для игры не нужны.

1. Войти в мир в творческом режиме, нажать **F6**.
2. Выбрать модель слева. В комплекте есть cubic-модели игрока и глаз.
3. **Animation >** переключает анимацию, **Play/Pause** управляет воспроизведением.
4. **Bone >** выбирает кость, **−/+** меняют её поворот по Z на 10 градусов.
5. **Q/E** поворачивают превью, колесо над превью меняет масштаб,
   колесо над списком прокручивает модели.
6. **Save form / Load form** сохраняют и загружают один локальный пресет
   `config/bbs/settings/forge-model-form.json`.
7. **Place** ставит блок модели на три блока вперёд от игрока, если место свободно.
   ПКМ по блоку открывает его форму; **Apply** применяет изменения на сервере.

Для внешней модели положить `model.bbs.json`, PNG-текстуру и при необходимости
`config.json` в `config/bbs/assets/models/<имя>/`, затем нажать **Reload**.
Имена моделей соответствуют путям папок, например `player/steve`.
Приоритет ресурсов: глобальные `config/bbs/assets` → дополнительные
`saves/<мир>/bbs/assets` → встроенные ресурсы. Папка мира сейчас подключается
для одиночной игры; пересылки ассетов удалённым клиентам нет.
Подкаталоги `/shapes/` отдельными моделями не считаются.

Команда с уровнем доступа 2: `/bbs model <имя> [анимация]`.
Для уже размещённого блока: `/bbs set <x> <y> <z> <данные-формы>`.
Формат данных — сериализация BBS `DataToString`, сохраняющая числовые типы,
а не произвольная структура vanilla NBT. UI размещает и редактирует только
для творческого игрока; сервер проверяет расстояние и загруженность чанка.

## Архитектура сборки

- Gradle **8.12**, RetroFuturaGradle **1.4.6**, MCP `stable_39`.
  Gradle проверен на JDK 21; компиляция и Minecraft работают через toolchain Java 8
  (в проверках Temurin `1.8.0_504`). Foojay загружает JDK 8 при его отсутствии.
- `gradle/forge-core.txt` явно перечисляет **157** переносимых классов оригинального
  `src/main/java`: данные, ресурсы, cubic loader/геометрия, анимации/Molang,
  позы/трансформации и независимая часть keyframes/values/math.
  `prepareBbsCore` копирует их в generated source set. Править нужно оригиналы,
  а не файлы внутри `build/generated`.
- `src/forge/java` содержит Forge lifecycle, клиентский рендер и UI,
  модельный блок/TileEntity, пакеты/команды и минимальные платформенные классы BBS.
  `src/forge/resources` содержит metadata, языки и vanilla-модель предмета.
- Остальные современные исходники сохранены, но в эту сборку не включены.
  Предыдущие Fabric-конфигурации сохранены в `gradle/legacy-fabric` как справка.
  Это не одновременная сборка обеих платформ из одной конфигурации.
- `src/forgeTest` — проверки именно перенесённого ядра. Современный набор тестов
  не запускается, потому что зависит от ещё не перенесённых систем.
- `src/aihelper` — отдельный тестовый Forge-мост для HTTP-протокола соседнего
  `../ai_helper`. Он не входит в дистрибутив BBS. Оригинальный `tools/mc.py`
  используется для запуска, управления игрой, скриншотов и остановки.

В оригинальных классах точечно заменён несовместимый с Java 8 синтаксис:
record, pattern matching, switch expressions, `List.of`, `Stream.toList`.
Для `KeyframeLoop` сохранены value equality/hash semantics.
SLF4J на платформенном пути заменён Log4j, GLFW/LWJGL 3 — LWJGL 2,
современные матрицы/буферы Minecraft — JOML + `GlStateManager`/`BufferBuilder`.
JOML `1.10.5` встроен; его Java 9 `module-info` удаляется из runtime JAR,
поскольку старый ASM Forge не умеет читать этот класс.

## Что работает и что упрощено

| Система | Состояние этой сборки |
| --- | --- |
| Forge lifecycle | `@Mod`, sided proxies, native registries, client keybind, server command |
| Ресурсы BBS | Оригинальные `Link`, `AssetProvider`, external packs; встроенный classpath index |
| Cubic-модели | Оригинальный `.bbs.json` loader, иерархия/pivots, кубы/UV, встроенная геометрия mesh |
| Текстуры/config | PNG через `DynamicTexture`, scale, texture, список внешних animations; прочие поля config пока не применяются |
| Анимации | Оригинальные Molang/keyframes и вычисление костей; ручной выбор одной анимации; время от мировых тиков |
| ModelForm | Подмножество: model, texture, pose, transform, animation, playing, frame; это не полный прежний Value API |
| Рендер | Native Tessellator, текстуры/цвета, простое затенение граней, кости и поза; GUI и world TESR |
| Блок модели | Сериализация формы в NBT, vanilla update packets, server-thread изменения, сохранение в мире |
| Интерфейс | Небольшой `GuiScreen` для просмотра и проверки форм; не полный Dashboard/редактор моделей |

Превью имеет фиксированный начальный масштаб; общих gizmo, выбора модели мышью
в 3D и редактирования геометрии пока нет. Кнопки интерфейса этого этапа на английском.
Все активные анимации привязаны к мировым тикам, поэтому отдельной временной
шкалы формы и полного набора BBS animation states пока нет. Контекст актёра
в Molang не подключён. Произвольные современные формы/проекты нельзя считать
совместимыми: поддержанное подмножество сохраняется, остальные поля не переносятся.

## Использование bb-sources

Изучались исходники соседнего `../bb-sources`; донорский проект целиком не копировался.
В коде платформенного слоя адаптированы следующие подходы:

| Референс | Применение в порте |
| --- | --- |
| Blockbuster `Blockbuster.java`, `CommonProxy`, `ClientProxy` | Forge lifecycle, разделение клиента и сервера, регистрация блока и рендера |
| Blockbuster `api/ModelPack.java` | Сканирование model packs, встроенные и внешние ресурсы; порядок приоритетов сохранён по правилам BBS FS |
| Blockbuster `ModelCustomRenderer`, `TileEntityModelRenderer` | Native GL matrix stack, Tessellator/BufferBuilder, world TESR; геометрия и вычисление позы остаются BBS |
| Blockbuster `TileEntityModel` | NBT и синхронизация модельного блока; полезная нагрузка заменена на сериализацию формы BBS |
| McLib `GuiBase` | Native GuiScreen и события мыши/клавиатуры для первой панели моделей |
| Старые build.gradle Forge-проектов | Проверка платформы/маппингов/Java 8; вместо устаревшего ForgeGradle 2.3 выбран RFG |

## Отложенные системы

Это сознательная граница первой базы; соответствующие современные исходники сохранены:

- Полный Dashboard, редакторы моделей/форм/фильмов, timeline UI, undo/redo,
  остальные формы/морфы, актёры, запись действий, камеры и библиотека пресетов.
- IK/constraints, физика/сварки/сплайны, shape keys и контроллеры, расширенные
  материалы и настройки рига. Наличие полей в исходном loader не означает,
  что их поведение уже подключено к Forge-рендеру.
- Отдельные загрузчики OBJ/BOBJ/VOX/GEO/JEM. Встроенные mesh в `.bbs.json`
  имеют путь отрисовки, но игровой прогон этого этапа проверял именно кубы.
- Iris/Sodium/Distant Horizons/Veil и другие современные интеграции не включены:
  базовый рендер использует vanilla Forge. Shader parity, тени и совместимость
  с OptiFine пока не проверялись.
- Audio/video/media, Minema/экспорт кадров, система аддонов и Fabric API.
- Автоматическое наблюдение за файлами, полный resource-pack pipeline,
  сетевое распространение ассетов и полноценная multiplayer-проверка.

Следующий этап: общий Forge UI слой и полноценный ModelForm/менеджер форм,
затем actor/entity adapter и film/timeline. После этого можно подключать
редактор геометрии, сложные риги и независимые форматы моделей по отдельности.

## Воспроизведение проверок

Команды PowerShell из корня проекта. Не пересобирать классы при работающем
dev-клиенте; сначала остановить только соответствующий тестовый процесс.

```powershell
.\gradlew.bat build
$env:AIH_PORT = '25612'
python ../ai_helper/tools/mc.py launch --no-wait
python ../ai_helper/tools/mc.py wait-ready --timeout 120
python ../ai_helper/tools/mc.py wait-world --timeout 120
python tools/forge1122/smoke.py
python ../ai_helper/tools/mc.py stop
```

Для проверки распространяемого JAR после остановки dev-клиента:

```powershell
python ../ai_helper/tools/mc.py launch --no-wait --gradle-args '-PforgeReleaseTest runObfClient'
python ../ai_helper/tools/mc.py wait-ready --timeout 120
python ../ai_helper/tools/mc.py wait-world --timeout 120
python tools/forge1122/smoke.py --release
python ../ai_helper/tools/mc.py stop
```

Dev-мир находится в `run-forge1122`, JAR-прогон — в `run-forge1122-obf`.
Мост сам входит в плоский creative-мир `ai_test`. Smoke меняет только этот
тестовый мир и устанавливает туда fixture `helper_drone`; проверяет путь
игрового каталога перед изменениями. У обеих сред порт 25612, поэтому запускать
их нужно по очереди. `prepareObfModsFolder` обслуживает только временный
`run-forge1122-obf/mods`: вручную установленные туда моды будут заменены.

Автоматические проверки:

- 5 JUnit: оригинальный Steve (37 костей, конечные координаты/UV), реальная
  анимация `helper_drone`, roundtrip позы/формы, KeyframeLoop, приоритет packs.
- Игровой smoke: загрузка BBS, вход в мир, reload внешней модели и её текстуры,
  6 анимаций и изменение вычисленных костей, Save/Load позы через UI,
  Place/Apply через настоящий серверный пакет, ПКМ по модели,
  точное сохранение NBT после выхода и входа, наличие кадров и отсутствие GL errors.
- Скриншоты UI и мира просматриваются визуально; HTTP-успех не заменяет эту проверку.

Результат 2026-10-04: `build` и все 5 JUnit успешны. Описанный игровой сценарий
успешно пройден через `ai_helper` и в dev-клиенте, и с готовым reobfuscated JAR
из `mods` в `runObfClient`; оба набора скриншотов просмотрены. Обнаруженные
ошибки module-info, vanilla item model и отключения тестового клиента исправлены
и перепроверены. Для отдельного helper JAR добавлена явная зависимость
`required-after:bbs`, необходимая для правильного порядка загрузки Forge.

Отчёты: `build/test-results/test/`, `build/reports/forge1122-smoke.json`,
`build/reports/forge1122-release-smoke.json`; скриншоты — `screenshots/ai/`
в соответствующем игровом каталоге. Проверка `/log` покрывает время после
инициализации helper; полный `logs/latest.log` проверяется отдельно.
Старый Forge в RFG пишет диагностику Maven layout и отсутствующей подписи FML
на уровне ERROR ещё до загрузки BBS. Это сохранённые сообщения окружения;
их нельзя выдавать за полностью чистый лог или скрывать общей фильтрацией.

Проверка dedicated server, нескольких клиентов и текстурного override формы
отдельным игровым сценарием пока не выполнена.
